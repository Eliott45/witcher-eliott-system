# The Witcher — Eliott

Самостоятельная неофициальная система для **Foundry VTT 14**. Первый этап — основа боя. Код и интерфейс Death March не копируются; зависимости от этой системы нет.

Иконки `icons/…` загружаются из самого Foundry и не включаются в архив системы.
SVG в `assets/icons` нарисованы для этого проекта; графика других игровых систем
не используется. Ресурсы тестового мира (например, портреты игроков) не входят в пакет.
Проект не одобрен и не поддерживается R. Talsorian Games; упоминаемые материалы
принадлежат RTG и его лицензиарам. Перед публичным бесплатным релизом требуется
проверить весь контент по [Homebrew Content Policy](https://rtalsoriangames.com/homebrew-content-policy/):
краткие пересказы и автоматизация допустимы, полные тексты книги и чужие иллюстрации
не должны входить в релиз. Этот README не подтверждает завершение такого аудита.

## Что уже есть

- Новые сцены: квадратная сетка, **1 клетка = 2 метра**. Размер клетки в пикселях настраивается отдельно под карту.
- Новые персонажи и NPC: обычное зрение **360°**. Стены и освещение обрабатывает Foundry.
- Красная стрелка направления и полупрозрачный серый полукруг сзади токена. При повороте `0°` персонаж смотрит вверх; стрелка и проверочный конус поворачиваются вместе.
- **ПКМ по своему токену → «Проверить обзор 180°»**: временно посмотреть только вперёд. Повторное нажатие или снятие выделения возвращает обычный обзор. Предпросмотр работает только у нажавшего игрока и не меняет документы или обзор других игроков.
- Персонажи используют связанные токены. NPC — несвязанные, чтобы экземпляры противников имели отдельные ресурсы.
- Лист персонажа по расположению блоков ориентирован на PF2e: ресурсы и производные показатели слева, имя сверху, портрет и сведения о происхождении в основной части, пол и возраст ниже. Текущие ПЗ и Выносливость вводятся вручную; изменение параметров не лечит персонажа и не восстанавливает ресурсы. ПЗ могут быть отрицательными.
- Семь вкладок: **«Главная»**, **«Навыки»**, **«Инвентарь»**, **«Действия»**, **«Биография»**, **«Семья»** и **«Эффекты»**. У активной вкладки показаны иконка и название, у остальных — иконки с подсказками. Меню справа позволяет скрывать вкладки. В биографии — внешность, черты характера, связи и союзники, враги, предыстория и заметки сессии. В семье — общие сведения, родители, братья и сёстры. Текстовые разделы сворачиваются; поля сохраняются при завершении редактирования.
- **Навыки**: 49 общих навыков и отдельные записи для каждого языка из присланных правил. Список сгруппирован по характеристикам и поддерживает поиск. У названий — подсказки с описанием, ориентирами мастерства 10/13/16/20 и пометкой сложных навыков (2). Это не фиксированные СЛ. Переключатель «Изменить уровни» открывает ввод целых неотрицательных уровней. Основа = действующая характеристика + уровень + бонусы; наведение на бонус или основу раскрывает источники и расчёт. Штрафы ранения и смерти затрагивают характеристику, не уровень навыка.
- **Способности** находятся в навыках. Способности выбранной расы появляются автоматически и открывают описания из компендиума. Можно перетащить Item типа «Способность» из любого компендиума/списка предметов, создать свою, изменить или удалить добавленную запись. Известные расовые бонусы учитываются и при выдаче другой расе; одинаковые ID правил не складываются повторно. Свои описательные способности не получают выдуманных правил. «Доверие» включает +1 к Харизме, Соблазнению и Убеждению против людей. Счётчик «Упрямства» показывает оставшиеся из трёх использований, поддерживает расход, возврат и сброс; сам переброс пока выполняется вручную по описанию.
- **Инвентарь** пока хранит перетаскиваемые предметы с открытием и удалением; вес и применение снаряжения ещё не реализованы. **Действия** — подготовленная вкладка без боевой автоматизации.
- Компендиум **Witcher → «Языки»** содержит **«Язык: Всеобщий (2)»**, **«Язык: Старшая Речь (2)»** и **«Язык: Краснолюдский (2)»** с описаниями. Кнопка рядом с разделом языков открывает компендиум. Перетаскивание добавляет отдельный навык с уровнем 0; повторное перетаскивание сохраняет существующую запись и её уровень. Старые записи с русскими или английскими названиями распознаются. Свои языки можно по-прежнему добавлять вручную. (2) — двойная стоимость изучения и развития, а не бонус к броску. Новые записи не выдают владение языком автоматически по расе или региону.
- Основные параметры находятся **на главной**, под сведениями о персонаже. В обычном режиме показаны итоговые значения. Переключатель «Изменить» справа от заголовка открывает ввод базовых значений **0–100**, включая Удачу. Наведение на число показывает базу, источники бонусов и штрафов, ограничение Эмпатии ведьмака и штраф ранения. Подсказки открываются над названием с «?», а не над всей карточкой или её сокращением. У каждого параметра есть кубик: **`1d10 + текущее значение`**, с учётом ранения, от имени персонажа и с приватностью чата. Пустое значение означает «не заполнено»; ноль — допустимое значение. После заполнения ТЕЛ и ВОЛИ максимумы ПЗ и Выносливости рассчитываются автоматически, в том числе для полосок токена. Старые максимумы сохраняются, пока эти параметры не введены.
- **Цепочки d10** работают в проверках параметров, навыков и инициативе. Первая 10 складывается со следующими бросками; первая 1 не учитывается, а следующие результаты вычитаются из базы. Только 10 продолжает цепочку: `10 → 1 = 11`, `1 → 10 → 1 = −11`. Удача и прочие бонусы применяются отдельно и не меняют тип критического результата. В одном сообщении показаны все натуральные грани, сумма цепочки и общий итог. Кубы передаются Dice So Nice последовательными бросками. УСТ и обычная панель кубов используют прежние броски без цепочек. Для макросов и ручных проверок доступна формула `/r 1d10wc + 8` (где 8 — база).
- **Удача** находится под именем: щелчок по 4 выбирает первые четыре доступных очка и подсвечивает их зелёным. Повторный щелчок отменяет выбор. Следующий бросок от имени этого персонажа получает +4 с подписью в чате; после отправки эти точки зачёркиваются. Поддерживаются броски параметров, панель кубов, обычные команды чата и инициатива (с обновлением трекера). УСТ сохраняет выбранную Удачу для следующего броска. Ошибка или отмена создания сообщения не тратит очки. Кнопка восстановления начинает новый запас на сессию.
- Подсказки слева показывают формулы с числами персонажа: `A = floor((ТЕЛ + ВОЛЯ) / 2)`; максимумы ПЗ/STA — `A × 5`, Отдых — `A`, УСТ — `min(10, A)`, Порог ранения — `floor(максимум ПЗ / 5)`. Порог стоит сразу после ПЗ, Отдых — после Выносливости. Бег — `СКОР × 3` м, Прыжок — `floor(Бег / 5)` м, переносимый вес — `ТЕЛ × 10` кг. Текущий вес — **0**, без ручного ввода, до добавления инвентаря. **«Предел магии (Энергия)»** пока задаётся вручную, до добавления профессий.
- ПЗ и Выносливость не могут превышать свои максимумы: ограничения действуют при подготовке старых данных, импорте и изменениях из листа, токена или макроса. Снижение максимума также ограничивает текущий ресурс. ПЗ могут быть отрицательными, Выносливость — не ниже 0.
- **«Испытание УСТ»** показывает расчёт порога при наведении на число в чате и не расходует выбранную Удачу. Оно отправляет обычный `1d10` в чат с результатом успеха/неудачи, от имени персонажа и с текущей приватностью чата. Успех — строго ниже УСТ, равенство — неудача. Предел 10 и строгое сравнение соответствуют [пояснению авторов](https://rtalsoriangames.com/2018/09/21/the-sages-answers-part-18/).
- В меню токена и списке эффектов доступны **«Дезориентация»**, **«Дезориентация от истощения»**, **«Без сознания»**, **«При смерти»** и **«Смерть»**. Обычная дезориентация запрещает движение, действия и защиту; весь ход можно потратить на испытание УСТ. Успешное испытание или попадание снимает её. Пока атаки не автоматизированы, попадание определяется по уменьшению ПЗ; попадание без урона отмечается мастером вручную.
- При падении STA до 0 или ниже автоматически накладываются **«Без сознания»** и **«Дезориентация от истощения»**. В этом случае разрешён только **Отдых**: кнопка под показателем REC восстанавливает столько STA, сколько указано в REC, не выше максимума. При STA > 0 снимается только потеря сознания. Для снятия дезориентации нужно накопить `min(20, максимум STA)` и успешно пройти испытание УСТ. До порога кнопка УСТ заблокирована; в листе виден оставшийся запас до испытания. Урон не снимает вариант от истощения. Отдельно наложенная потеря сознания не лечится обычным изменением положительного запаса STA.
- Пока персонаж дезориентирован или без сознания, проверки параметров с листа недоступны, перемещение и поворот токена игроком блокируются. Мастер может перемещать токены принудительно и вручную снимать состояния. Отдых и УСТ доступны по правилам конкретного состояния; обязательные испытания смерти остаются доступны. Автоматический учёт потраченных действий и полных ходов пока не ведётся.
- Результат УСТ снимает эффект после появления сообщения и завершения Dice So Nice. Повторное истощение или трата STA ниже нужного порога во время броска не позволяет старому результату снять новое состояние. Состояния при нулевой STA восстанавливаются после входа ведущего, включая несвязанные NPC-токены; пустые листы 0/0 не затрагиваются.
- При ПЗ строго ниже порога отображается тяжёлое ранение: эффективные ИНТ, РЕА, ЛВК и ВОЛЯ делятся пополам с округлением вниз. Базовые значения не изменяются; уменьшенные показаны рядом. Максимумы ресурсов и сам порог не уменьшаются вслед за штрафом. При восстановлении ПЗ штраф снимается. Инициатива в трекере Foundry — `1d10 + текущая РЕА`; при ранении используется уменьшенная РЕА. При ПЗ ≤ 0 этот штраф заменяется штрафом состояния «При смерти».
- **При смерти:** при переходе ПЗ к 0 или ниже автоматически добавляется состояние и проводится испытание со штрафом 0. Восемь параметров делятся на 3 с округлением вниз; Удача, максимумы ПЗ/Выносливости, базовая УСТ и Отдых сохраняются. Производные движение и переносимый вес используют уменьшенные параметры. Рядом с ПЗ — счётчик штрафа, порог с формулой и кнопка «Испытание смерти». Владелец персонажа или мастер может исправить счётчик вручную.
- **Испытание смерти:** обычный `1d10 < базовая УСТ − штраф + выбранная Удача`, без критических цепочек. Равенство — провал. Удача повышает порог, не значение кубика, и тратится только после отправки сообщения. Новый урон в состоянии при смерти и каждый следующий раунд увеличивают штраф на 1 и вызывают испытание. Несколько связанных токенов одного актёра не дублируют бросок. Каждое нажатие кнопки «Испытание смерти» также добавляет +1 перед броском, используя текущее значение счётчика. Отмена или ошибка отправки сообщения возвращает эту прибавку; ручная правка во время броска сохраняется. Первый автоматический бросок при падении ПЗ до 0 остаётся со штрафом 0.
- В состоянии **«При смерти»** по краям листа и вокруг портрета пульсирует тёмно-красное свечение. После смерти оно сменяется неподвижной тёмной виньеткой, а портрет становится чёрно-белым. Эффект не перехватывает клики и прокрутку; при системной настройке уменьшения движения пульсация отключается.
- Успех **не стабилизирует** персонажа. Провал накладывает **«Смерть»** после показа результата и завершения Dice So Nice, убирает «При смерти» и прекращает испытания. Лечение живого персонажа выше 0 снимает «При смерти» и сбрасывает штраф; лечение погибшего не снимает «Смерть». Игрок не может снять эти состояния кнопкой в листе или меню токена; ручная отмена доступна мастеру. У существующих персонажей и NPC-токенов с ПЗ ≤ 0 при входе ведущего добавляется состояние без ретроспективного броска. Пустой лист 0/0 не считается умирающим.
- Троеточие справа от вкладок открывает настройки их видимости. Можно скрыть любую вкладку, оставив хотя бы одну. Если скрыта текущая, открывается первая доступная. Выбор вкладок и свёрнутых разделов сохраняется отдельно для каждого пользователя и листа, включая листы, доступные только для чтения. Содержимое скрытых вкладок не удаляется.
- Лупа рядом с расой или регионом открывает модальное окно выбора с поиском по названиям и бонусам. Есть фильтры, просмотр описаний, подтверждение, отмена и очистка выбора. Название выбранной расы/региона и троеточие открывают описание из компендиума.
- Компендиумы **«Расы»** (человек, эльф, краснолюд, ведьмак) и **«Расовые способности»** (13 записей). В описании расы показаны её способности и ссылки на отдельные записи. Бонусы, штрафы, иммунитеты и лимиты пока учитываются вручную.
- Компендиум **«Регионы происхождения»** содержит 23 региона со скринов: 10 северных, 11 нильфгаардских, 2 из земель Старших Народов. Описания включают указанные бонусы; навыки и эффекты автоматически не меняются. Ведьмак может выбрать регион для биографии, но бонус ему не положен: это отмечается в листе и окне выбора.
- **«Положение семьи»** на главной открывает такой же поиск, как раса и регион. В компендиуме — 21 вариант из таблицы: по 7 для северян, нильфгаардцев и нелюдей, с описанием, диапазоном броска и наградами. Начальный фильтр подбирается по расе и региону; его можно сменить. У ведьмаков поле скрыто, награды недоступны. Выбор хранится отдельно от свободного текста о семье. Численные бонусы привязаны к выбору жизненного пути; предметы, знакомые и друзья автоматически не выдаются.
- Необязательный раздел **«Друг, оказавший влияние»** расположен в биографии и сворачивается по заголовку. Лупа открывает 30 вариантов из таблицы с поиском и фильтрами, название — описание влияния и ссылки на памятные вещи. Выбор можно очистить; он доступен и ведьмакам. Бонусов и автоматической выдачи предметов нет.
- Компендиум **«Предметы»** разделён на две внутренние папки: **«Семья»** (10 предметов с базовыми описаниями пользователя) и **«Друг»** (28 памятных вещей из таблицы, пока без описаний). Повторяющиеся вещи используют одну запись. Численные бонусы остаются в описаниях жизненного пути; предметы не содержат эффектов. Из описаний положения семьи и влияния друга можно открыть соответствующие предметы. Афиша и билет представлены отдельно как альтернативы.
- Все шесть компендиумов находятся в папке **Witcher**. В существующем мире после перезапуска сервера и входа ведущего новый компендиум добавляется в неё; расположение ранее организованных компендиумов сохраняется.
- Компактная панель кубов с непрозрачным фоном под полем сообщения: **d4, d6, d10, d12, d20, d100**. Клик добавляет куб, ПКМ или Shift+клик убирает один. Счётчики показаны на выбранных кубах; кнопка с ползунками раскрывает поля количества. Кнопка «Бросить» отправляет весь набор одной формулой, например `2d6 + 1d10`. После успешной отправки набор сбрасывается; при ошибке или отмене сообщения модулем остаётся для повторной попытки. Кнопка сброса очищает набор вручную. Используется обычная команда `/r` с текущим режимом видимости и говорящим, черновик сообщения сохраняется. Панель работает в боковом чате и его отдельном окне.
- Клик по портрету открывает стандартное окно изображения Foundry; ведущий может показать его игрокам через меню этого окна. Карандаш на портрете позволяет заменить изображение.
- Русский и английский интерфейс.

Это ещё не полноценная реализация правил: атаки, защиты, применение урона и механика снаряжения не реализованы. Численные бонусы расы, семьи и региона работают в параметрах и навыках; Доверие включается игроком для общения с людьми. Репутация и природная броня пока рассчитываются в `system.statistics` без отдельных интерфейсов. Бонусы семьи и региона исключены для ведьмаков. Предметы не дублируют бонусы жизненного пути.

## Первый запуск

1. Папка должна находиться в `Data/systems/witcher-eliott-system` — текущий проект уже расположен правильно.
2. Перезапусти Foundry, чтобы сервер обнаружил новый `system.json`.
3. Создай отдельный мир с системой **The Witcher — Eliott**.
4. Создай сцену: квадратная сетка, дистанция `2`, единицы `m`. Оставь включённым зрение токенов.
5. Для дневной тестовой сцены включи глобальное освещение; для тёмной добавь источник света.
6. Создай персонажа, включи «Изменить» у основных параметров и заполни их, выставь текущие ПЗ/Выносливость и перетащи его из списка актёров на сцену.
7. Выдели один токен и поверни его через **Shift + колесо мыши**. Ведущий без выделенного токена видит сцену целиком; также можно проверить видимость из учётной записи игрока с правами владельца.

Проверь линейкой: одна клетка по горизонтали — 2 м, пять клеток — 10 м. Затем размести противников впереди и позади персонажа: в обычном режиме видны оба. Включи проверку обзора через кнопку с человеком в меню токена — задний противник должен исчезнуть. Поверни персонажа, выключи проверку и повтори со стеной.

Серый полукруг — подсказка о направлении тыла, он сам не скрывает карту и токены. Более узкий «ограниченный» конус из правил пока не реализован. Предпросмотр выбирает один токен, чтобы обзор нескольких выбранных персонажей не складывался; для проверки сохраняй выбор одного токена.

Используется обычное зрение Foundry. Дальность зрения по умолчанию `0` означает отсутствие собственного зрения в темноте, а не запрет видеть освещённые области. Для проверки нужен свет. Режимы ночного зрения пока не задаются автоматически.

Туман войны может сохранять исследованные участки карты позади персонажа; это не текущая видимость токенов. Несколько выбранных/доступных токенов также могут объединять обзор по правилам Foundry.

## Настройки и существующие документы

Параметры сетки задаются в `system.json` и служат значениями по умолчанию для новых сцен. Импортированные карты сохраняют свою сетку; при необходимости измени её в настройках сцены.

Угол по умолчанию `360°` и угол предпросмотра `180°` задаются в `scripts/config.mjs`. Для исключений используй **Настроить прототип токена → Зрение**. Более узкий угол, настроенный вручную, не расширяется предпросмотром. Копирование и импорт сохраняют явно заданные настройки.

При первом входе ведущего после обновления до 0.2 старый угол `180°` меняется на `360°` у персонажей, NPC и уже размещённых токенов на всех сценах. Это однократное обновление; другие углы, освещение, дальность зрения и поворот сохраняются. Значение поворота `0°` теперь соответствует стрелке вверх. После обновления перезагрузи страницу мира на всех клиентах.

## Как устроен проект

Возраст хранится в `system.details.age` как целое неотрицательное число лет, пустое значение — `null`. Верхнего ограничения нет. Раса хранится в `system.details.race` как стабильный ID (`human`, `elf`, `dwarf`, `witcher`), а не переведённое название. Старые персонажи получают пустые поля; автоматического выбора расы нет. Изменения сохраняются при вводе.

Пол хранится в `system.details.gender` как произвольная строка, по умолчанию пустая. Он не влияет на игровые характеристики.

Биография хранится в `system.biography`: `appearance`, `personality`, `allies`, `enemies`, `backstory`, `sessionNotes`, а также `family.history`, `family.parents`, `family.siblings`. Это обычный многострочный текст с пустыми начальными значениями. Старые персонажи получают новые поля без изменения остальных данных; прежнее поле `system.notes` сохраняется отдельно.

Положение семьи хранится в `system.details.familyStatus` как стабильный ID из `scripts/data/family-statuses.mjs`. `familyRewardEligible` возвращает `false` для ведьмаков и отсутствующего выбора. Смена расы скрывает поле, но сохраняет ранее выбранное положение семьи. Записи из `scripts/data/equipment.mjs` — обычные Item типа `equipment` без автоматизации.

Влияние друга хранится в `system.details.influentialFriend` как стабильный ID из `scripts/data/influential-friends.mjs`, по умолчанию пустая строка. Компендиум `influential-friends` использует тип Item `influence`. Эта справочная запись не меняет навыки, ресурсы и предметы персонажа. Смена расы не стирает выбор.

Каталог предметов содержит источник `family` или `friend`; сборка использует его для штатных папок внутри компендиума. ID старых семейных предметов сохранены. Папки хранятся в подуровне LevelDB `folders` и в читаемом файле `pack-sources/equipment.folders.json`.

Настройка `sheetPreferences` имеет область `user` (Foundry 14) и хранит `hiddenTabs` и `collapsed` по UUID актёра. Она не меняет данные персонажа или настройки других игроков. Скрытие вкладки — настройка отображения, не ограничение доступа к информации.

Регион хранится в `system.details.origin` как стабильный ID из `scripts/data/origins.mjs`. Старые актёры получают пустое значение. `getOriginBonus` возвращает описание бонуса либо `null` для ведьмака/отсутствующего региона. Модификаторы навыков из `background-modifiers.mjs` соблюдают то же исключение. Смена расы не стирает выбранный регион.

Каталог `scripts/data/races.mjs` содержит расы и отдельные способности со стабильными ID, например `human.stubbornness`. Из него и русских описаний в `lang/ru.json` собираются настоящие Item-компендиумы. `system.ruleId` сохраняет ID правила, а `system.abilities` у расы содержит UUID её способностей. Постоянные ID документов объявлены в `scripts/data/compendiums.mjs`; их нельзя перенумеровывать. При расчёте учитывается объединение способностей выбранной расы и добавленных Item типа `ability`, без дублирования правил. Исходные значения параметров и уровни навыков не изменяются.

Уровни хранятся в `system.skills` по стабильным ID из `scripts/data/skills.mjs`, по умолчанию 0. Языки — массив `system.languages` с `id`, `name`, `level`. В `system.abilityState` находятся `trustEnabled` и `stubbornnessUsed` (0–3). При смене расы добавленные способности и введённые уровни сохраняются; встроенные способности обновляются согласно новой расе. Разделы описаний обогащаются стандартным TextEditor Foundry, добавленные способности — обычные редактируемые встроенные Item.

Способности, настройки зрения, боевые заметки и служебные подсказки убраны из листа. Старые заметки остаются в данных актёра, чтобы не терять ранее введённый текст. Система работает самостоятельно; PF2e использовался только как первоначальный референс.

Quick Insert использует объявленные системой типы Item `race`, `ability`, `origin`, `familyStatus`, `equipment` и `influence`. В версии 3.7.8 его инициализация фильтров падает, если система не объявляет `documentTypes.Item`; манифест содержит все эти типы. Модуль и его назначение Ctrl+Пробел не изменяются. После перезапуска мира модуль может индексировать новые компендиумы согласно своим настройкам доступа и индексации.

Система, в отличие от модуля, определяет собственные типы актёров, структуру их данных и листы. Основные части:

- `system.json` — манифест, совместимость, типы актёров, ресурсы токена и сетка.
- `scripts/witcher.mjs` — регистрация моделей, листов и обработчиков Foundry.
- `scripts/data/witcher-actor-data.mjs` — сохраняемые данные персонажей и NPC.
- `scripts/data/races.mjs` — каталог рас и способностей с идентификаторами для будущей автоматизации.
- `scripts/data/witcher-reference-data.mjs`, `scripts/data/witcher-race-data.mjs` — модели Item.
- `pack-sources/` — читаемые JSON-записи; `packs/` — готовые базы LevelDB для Foundry.
- `scripts/combat/token-defaults.mjs` — начальные настройки прототипа токена.
- `scripts/canvas/witcher-token.mjs` — маркеры направления и локальный предпросмотр зрения.
- `scripts/combat/token-hud.mjs` — кнопка проверки обзора в меню токена.
- `scripts/chat/dice-tray.mjs`, `scripts/chat/dice-pool.mjs` — панель кубов и подготовка общего броска.
- `scripts/sheets/witcher-actor-sheet.mjs` — лист на ApplicationV2.
- `scripts/sheets/witcher-item-sheet.mjs` — описания рас и способностей на ApplicationV2.
- `templates/actor-sheet.hbs`, `styles/witcher.css`, `lang/` — разметка, стили и переводы.

Установка npm-зависимостей не нужна: Foundry загружает исходные ES-модули, а готовые компендиумы включены в проект. После изменения JavaScript обнови страницу мира; после изменения манифеста перезапусти сервер.

После правки каталога или описаний пересобери компендиумы **при остановленном сервере Foundry** (используется библиотека LevelDB установленного Foundry; закрытие браузерной вкладки не освобождает базу):

```sh
npm run build:packs -- "E:/fvtt14/Foundry Virtual Tabletop/resources/app"
```

Сборка обновляет записи и папки со стабильными ID и сохраняет остальные документы. Можно указать названия нужных компендиумов после пути, например `equipment influential-friends`. Не редактируй поставляемые записи напрямую: при пересборке их содержимое обновляется из исходников. Для своих вариантов импортируй запись в мир.

Флаг `--sources-only` обновляет только JSON в `pack-sources`, не открывая живую базу. Для четырёх базовых боеприпасов есть отдельное обновление: при следующем входе/обновлении страницы активного мастера Foundry добавит отсутствующие записи и папку в «Предметы», исправит старую битую иконку и переведёт стандартные пачки в поштучный учёт, сохранив общий вес/стоимость и исходную блокировку компендиума. Копии в мире, персонажах и несвязанных токенах тоже исправляются. Это не общая синхронизация всех JSON-записей.

`quantity` — остаток отдельных предметов, `weight`/`price` — вес и цена одной штуки. `purchaseQuantity` — число штук, выдаваемых каталогом за одно добавление/покупку (обычно 1, для стандартных боеприпасов 10). Размер пачки не меняет единицу учёта в инвентаре. Старые пачки помечаются после пересчёта, чтобы повторное обновление и ручная смена размера продажи не умножали остаток.

Проверка исходников на Node.js 24+:

```sh
npm run check
npm test
```

Дополнительно можно проверить манифест, модели данных, сохранение биографии и необязательного друга, все 129 Item-записей, папки предметов, UUID-ссылки, исключения для ведьмаков, личные настройки вкладок, открытие описаний и шаблоны на локальном ядре Foundry:

```sh
npm run check:foundry -- "E:/fvtt14/Foundry Virtual Tabletop/resources/app"
npm run check:foundry -- "E:/fvtt14/Foundry Virtual Tabletop/resources/app" "D:/Foundry/Data/modules/dice-so-nice"
npm run check:quick-insert -- "D:/Foundry/Data/modules/quick-insert"
```

Укажи пути к своей установке. Проверки не запускают сервер. Проверка ядра воспроизводит все девять примеров цепочек с заданными гранями, сохраняет их через штатную модель чата и проверяет отдельное применение Удачи. Если передан путь к Dice So Nice, дополнительно проверяется порядок бросков через установленный DiceNotation; физическая анимация в браузере этой проверкой не запускается. Проверка Quick Insert воспроизводит ошибку в функции установленного модуля и проверяет её исправление, но не эмулирует нажатие клавиш или интерфейс поиска.

Приватный GitHub-репозиторий уже подключён как `origin`. Ссылки для публичной установки и обновления появятся после настройки распространения; сейчас система запускается из локальной папки.
