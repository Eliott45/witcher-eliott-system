# Лист существа и оружейные действия — 2026-10-05

## Реализовано

- Отдельный компактный лист существ для существующего Actor type `npc`: бой, инвентарь, сведения, редактирование, навыки, защиты, состояния, способности и добыча.
- Бандит и утопец в Actor-компендиуме «Бестиарий». Новый пустой NPC также предлагает оба профиля без необходимости импорта.
- Хват 1/2 руками; взятие оружия достаёт его из контейнера, лишнее оружие убирается. Старое `hands` остаётся требованием, `grip: 0` наследует его.
- Две быстрые / сильная атака, отдельные режимы лука и арбалета, печатная СА для NPC. Прицеливание, дистанция, ручной модификатор, бонус ТЕЛ, чат с отдельными бросками и кнопкой урона.
- Дополнительное действие: 3 ВЫН один раз за всё действие, −3 ко всем его проверкам. Общий механизм используется параметрами, навыками, профессиями, репутацией и магией. В боевом трекере повторное использование в том же раунде запрещено. Инициатива и спасброски не покупают действие.
- «Дикий» утопца использует ИНТ 7 только для Внимания/Выживания; иммунитет к яду запрещает наложение Отравления. Остальные особенности доступны как обычные способности.

## Источники и принятые решения

- Предоставленный PDF: стр. 48 (ТЕЛ), 151–157, 163–164 (атаки, прицеливание, защита), 270–271 (полный блок бандита; стр. 267 — начало раздела), 276–277 (утопец).
- [Официальная Errata v4](https://rtalsoriangames.com/wp-content/uploads/2022/03/RTG-WI-WitcherCoreErratav4.pdf): стр. 151 — дополнительное действие любого вида; стр. 271 — Борьба бандита 6 и точность арбалета +1. Поправки включены.
- [Sage’s Answers 13](https://rtalsoriangames.com/2018/09/04/the-sages-answers-part-13/): пояснения боевых бросков и устойчивости чудовищ к стали.
- NPC, включая бандита, используют СА своего оружия, а не быстрые/сильные атаки персонажа. Готовый урон из блока NPC уже содержит его бонус ТЕЛ; повторного прибавления нет. Кинжал бандита сохранён как 1d6 из блока, без замены на каталожный 1d6+2.
- Уязвимость утопца к огню сохранена описанием. Конкретный множитель не автоматизирован до проверки общего правила.

## Архитектура и совместимость

Duplicate-check: использованы существующие Actor `npc`, Weapon, Ability, навыки, ресурсы, состояния, inventoryWrite, очередь магии, Dice So Nice и чат Удачи. Нового типа Actor или второго хранилища атак нет. Добыча реагентов переиспользует существующий `harvest`, расширенный необязательной формулой количества. Метаданные существа не дублируют характеристики/инвентарь. Новые поля имеют безопасные значения по умолчанию. Версия 0.2.0 не менялась. Изображения SVG созданы внутри системы, без ресурсов сторонних систем.

## Продолжение: проверка в мире под GM

При реальном импорте обнаружена ошибка начальной сборки LevelDB: embedded Items хранились внутри записи Actor, хотя Foundry ожидает ссылки на отдельные записи `actors.items`. Исправлен общий сериализатор сборки с поддержкой вложенных ActiveEffect; добавлены проверки обратной сборки документов. Live migration восстанавливает пустые канонические записи через API Foundry и возвращает исходную блокировку компендиума. Уже импортированным пустым профилям предложена отдельная кнопка восстановления, без изменения характеристик и пользовательских предметов.

Под GM проверены новый NPC с профилем утопца, атака дополнительным действием (+13 → +10, 25 → 22 ВЫН), сохранение введённого с клавиатуры имени, а также импорт исправленного бандита с 3 оружиями, 3 частями брони ПБ 5, болтами и способностью. Для дальнейших проверок оставлены Actor «QA — Бандит (импорт)» и «QA — Утопец (бой) проверка». Ошибка загрузки звука `dice-so-nice/sounds/dicehit.mp3` относится к внешнему модулю; ошибок системы при проверке не появилось.

## Завершение продолжения: защиты и проверка импорта

- В общем блоке действий персонажа и NPC появились Уклонение, Смена позиции, Блок и Парирование. Используются текущий навык и эффективные характеристики; WA к защите не добавляется. Отдельный модификатор защиты позволяет учесть окружение и ситуацию.
- Переключатель повторной защиты списывает 1 ВЫН после сообщения и Dice So Nice; дополнительное действие при этом не расходуется. Выбор первой/повторной защиты остаётся явным, включая бесплатные защиты при активном уклонении. Блокирование снарядов требует щита; обычное парирование стрел/болтов недоступно.
- Из сообщения атаки можно бросить обычный 1d10 по таблице зон гуманоида или чудовища. Использованы исправленные диапазоны чудовища из errata; Удача не тратится, приватность сообщения сохраняется. Урон и зона каждого попадания бросаются отдельно.
- Щиты получили необязательный класс; старые каталожные щиты определяются по ruleId. Урон 0 использует таблицу удара рукой, явная формула предмета остаётся доступной. Когти больше не показывают бессмысленную надёжность 0/0. Болты нового профиля бандита используют существующую запись стандартных боеприпасов, включая надёжность и единицы учёта.
- Исправлено переключение вкладок NPC: Foundry требует класс `.tabs` у панели навигации. Исправление проверено живыми переходами Бой → Сведения → Инвентарь.

### Проверка источников и неоднозначности

Проверены предоставленные страницы 48, 80, 152 и 164; официальная [Errata v4](https://rtalsoriangames.com/wp-content/uploads/2022/03/RTG-WI-WitcherCoreErratav4.pdf), а также [Sage’s Answers — Finale](https://rtalsoriangames.com/2018/10/12/the-sages-answers-finale/) (WA не прибавляется к блоку и парированию). В errata нет отдельной числовой расшифровки удара средним/тяжёлым щитом. Минимальное решение с TODO: «на 2/4 уровня выше» трактуется как строки таблицы удара рукой, с ограничением последней опубликованной строкой. Мастер может заменить формулу урона щита. Парирование метательного оружия использует указанный на стр. 164 штраф −5 вместо обычного −3; стрелы и болты требуют отдельной способности.

### Аудит архитектуры и границы

Проверка готовности оружия вынесена в общий helper для атаки и защиты. Обе системы используют существующие Weapon/Actor/skills, очередь inventoryWrite и ожидание показа броска. Таблица случайных зон переиспользует определения прицеливания. Состояние повторной защиты хранится только в UI, без второй модели раунда в Actor. Добавлено одно совместимое необязательное поле Weapon `shieldClass`; нового типа предмета нет. Версии package.json/system.json остались 0.2.0.

Следующий самостоятельный этап: применение урона к выбранной цели с бронёй/серебром/сопротивлениями, автоматический износ при подтверждённом попадании или блоке, расход боеприпасов, критические ранения и специальные манёвры. В текущем UI эти последствия остаются ручными. Уязвимость утопца к огню пока представлена описанием, без непроверенного множителя.
